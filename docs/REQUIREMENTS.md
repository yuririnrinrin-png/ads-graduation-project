# 要件・合意事項（Grill 結果）

このドキュメントは、設計インタビュー（Grill）で確定した内容の記録です。実装・変更時はここを正とします。

## 1. ゴール

| 項目 | 決定 |
|---|---|
| 利用者 | 自社 EC の担当者 |
| 成功の定義 | ほぼそのまま商品ページに載せられる品質。1 商品あたり数分。合成のズレは担当がレビュー画面で短時間仕上げられること（自動で完璧は求めない） |
| 提供形態 | 社内向けブラウザ Web アプリ |
| 認証 | 共有の社内ログイン（ID/パスワード or Google）。人ごとの細かい権限は v1 対象外 |
| 同時利用 | v1 想定は同時ジョブ少数（目安 1〜2） |

## 2. 対象商品

| 項目 | 決定 |
|---|---|
| スコープ | 全カテゴリ対応（部位ルールはカテゴリで差し替え） |
| v1 の選択一覧 | **ネックレス**（ペンダント・チョーカー含む）／**ピアス**／**リング**／**ブレスレット** |
| 10 枚の型 | 役割（ディテール3／着用4／全身2／引き+インセット1）は共通。写す部位だけ変える |

### カテゴリ別の部位（着用シーン）

| カテゴリ | 着用 4 枚で主に写す部位 |
|---|---|
| ネックレス | 胸元〜顔（バストアップ） |
| ピアス | 顔まわり |
| リング | 手元 |
| ブレスレット | 腕まわり |

### ピアスの撮影方法（決定・2026-08-12）

撮影は他カテゴリと同じ「片耳分（1個）を3アングル」でよい。理由:

- ペア（2個並び）を1枚に撮ると、切り抜き処理で2つの物体を分離するのが不安定になる
- 片耳分だけなら他カテゴリと同じ「1商品3アングル」の流れのまま撮影できる

システム側は、その1個の切り抜きを鏡写しして両耳へ自動合成する。レビュー画面では
左右それぞれの大きさ・位置を個別にドラッグ調整できる（顔の大きさに応じた微調整用）。

シーン名（オフィス／カフェ／デート／休日）は全カテゴリ共通。  
新規ジョブ画面では、選んだカテゴリに応じて「着用シーンでは◯◯を写します」など部位ヒントを出す。

## 3. 入力

| 項目 | 決定 |
|---|---|
| 枚数 | 同一商品の角度違い **3 枚** |
| 撮影条件 | 白〜淡色背景。商品のみがはっきり写っていること。着用に使う**メイン写真はできるだけ正面**（新規ジョブ画面で案内。斜めでも生成は止めない） |
| カテゴリ | アップロード時に担当が手動選択 |
| 地金カラー | アップロード時に選択。表示は **YG / WG / PG**（PG＝ピンクゴールド。RG 表記は使わない） |
| メイン写真 | 3 枚のうち 1 枚を選択（切替可能）。着用合成のソースに使う |
| 対応関係 | 3 枚 → ディテール 3 枚にそのまま対応（背景差し替え）。着用 7 枚はメイン写真を軸 |
| 生成開始条件 | 必須項目が揃うまで「生成する」は無効（disabled）。未選択の案内を出す |

## 4. プリセット・見た目の選択

| 項目 | 決定 |
|---|---|
| 人物 | ブランド用プリセットから商品ごとに 1 人選ぶ。**1 ジョブ内は同一人物**（枠の再生成でも人物は維持） |
| ディテール背景 | プリセットから 1 つ選び、ディテール 3 枚で統一 |
| 全身トーン | 4 択から **ちょうど 2 つ**選ぶ。選択数「2/2」を表示。上限到達時は他を選べないようにする。服の細部は AI 任せ |
| 初期プリセット数 | 人物 **3**・背景 **4**・全身トーン **4**。あとから管理側で追加可能 |

背景プリセット例: 白大理石／トラバーチン／リネン／黒石  
全身トーン例: オフィス／休日／エレガント／リラックス

## 5. 生成品質・合成方針

| 項目 | 決定 |
|---|---|
| ディテール 3 枚 | AI 人物生成なし。切り抜き＋背景差し替え＋地金に合わせた色調整のみ |
| 着用・全身・引き | 人物は AI 生成。**商品はアップロード実物を切り抜いて合成**（AI にジュエリーを描かせない）。人物は**正面から左右約15°以内**。首と耳が見える髪型（耳かけダウンはカフェと引きの2枠のみ）。着用4枚は首元が開いた服。7枚は表情・向き・髪型・場面・服で差を出す（横顔・振り返りはしない）。参照顔も首・耳が見える写真 |
| 配置 | まず自動配置（ネックレス／ピアスは人物シーンから**顔の位置（矩形）を検出**し、顎の下＝鎖骨あたり／顔の左右＝耳あたりへ初期位置をずらす。検出失敗時は従来の固定アンカー。首の骨格ランドマークによる本格対応はしない）。プレビューで**大きさ・位置・回転**をつまみ調整 |
| パース（角度ズレ） | **3D的な自動補正はしない**。貼り付け感を和らげるため、(1) 薄い接触影 (2) 切り抜きの明るさをシーンにごく軽く合わせる（色は原本に寄せる） (3) 耳かけダウン枠のみ、髪マスクが取れれば髪をジュエリーの上に戻す (4) ネックレス/ピアスの**固定の小さな傾き**＋レビューでの手動回転。大きなズレは人手レビューで救う |
| レビュー | 10 枚一覧 → **ダメな枠だけ再生成**（実行前に軽い確認） → ZIP ダウンロード |
| インセット 1 枚 | 引き＝全身をもう 1 枚生成。右下インセット＝ディテールから担当が選択 |

## 6. 出力

| 項目 | 決定 |
|---|---|
| 形式 | 役割つきファイル名の **ZIP**（EC への自動アップロードは v1 対象外） |
| 比率・解像度 | すべて **1:1・2000×2000** |
| 保管 | 生成結果は **14 日で削除**。ZIP はダウンロード時に打包 |

## 7. 待ち時間・エラー

| 項目 | 決定 |
|---|---|
| 初回生成 | **2〜4 分**（進捗表示あり） |
| 単枠再生成 | 数十秒〜1 分目安 |
| 失敗時 | 段階名つきで失敗表示。最初から／失敗段階からリトライ可 |

進捗段階: `切り抜き → ディテール → 人物シーン → 合成 → 仕上げ`

## 8. v1 でやらないこと

- EC（Shopify 等）への自動アップロード  
- ユーザー個別の RBAC・詳細監査ログ  
- カテゴリの細分化（フープピアス、スタックリング等）  
- 印刷向け超高解像度（3000px 超）  
- ログインなしの公開 URL  
- 進捗中の途中成果物の先出し表示  
- 着用シーンの拡大比較モーダル・複数枠の一括再生成／一括 OK  
- パース（角度）の**本格的な**自動補正（実写角度に合わせた3D変形・AIによるジュエリー描画）。軽量な影・明るさ合わせ・肌色の乗算・固定チルト、および耳かけダウン枠の髪オーバーレイのみ（§5参照）  
- 首・耳の骨格ランドマーク検出による動的アンカー（顔の矩形＋固定オフセットのみ。§5参照）  
- 商品写真が正面かどうかの自動判定・生成拒否 

## 9. 未決（実装時に詰める）

優先順（上ほど先に決める）:

1. 画像生成 API の**コスト上限の具体値**（ジョブあたり呼び出し上限）。ベンダー候補は fal.ai でスパイク済み（下記）  
2. ~~人物の同一顔維持の実現手段~~ → **暫定決定:** fal.ai の PuLID on Flux（`fal-ai/flux-pulid`）。参照写真は `PresetPersona.imageKey`、無ければ Flux で生成した顔を参照に使う。本番用の参照写真セットは後で差し替え  
3. 人物・背景プリセットの中身（実デザイン・参照写真・プロンプト磨き）  
4. ホスティング先の本番構成  
5. 商品ページ側で「AI モデル使用」等の表記が要るか（ツール外方針含む）  

スパイクメモ（2026-08-12）:

- モデル: `fal-ai/flux/dev`（参照顔）+ `fal-ai/flux-pulid`（7シーン）  
- 目安呼び出し: 参照なし時 最大約 8 回/ジョブ（参照ありなら 7 回）  
- 課金単位は fal の megapixel 課金。上限金額は運用で決める  
- `FAL_KEY` 未設定時はローカル仮シーン（開発用）
